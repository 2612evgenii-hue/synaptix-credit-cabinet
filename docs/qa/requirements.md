# Чеклист требований

Что проверяем в готовом проекте. Страницы — по разбору [docs/requirements.md](../requirements.md), не по отдельному прочтению PDF.
Статус на 2026-10-20: работающего кабинета нет, поэтому ни один пользовательский пункт не закрыт.

Критерии жюри со стр. 9 (целостность процесса, понятность клиенту и банку, согласованность частей, готовность к проверке) смотреть по сценариям целиком. Отдельной галочки у них нет.

## Наши предложения

Это решения команды для реализации. Пока код их не подтвердил, в чеклист задания они не входят. Если расходятся с заданием, побеждает задание.

| Предложение | Где записано | Как относиться на проверке |
| --- | --- | --- |
| Статусы от `DRAFT` до `DISBURSED_SIMULATED`, включая `NEEDS_INFO` | `docs/state-machine.md` | Сверять продукт с диаграммой после того, как команда её примет. Имена статусов на экране могут быть человеческими |
| Оценка риска и кредитное решение — разные шаги | `docs/architecture.md` | Одинаковый риск сам по себе не обязан давать одинаковые условия |
| Сумма хранится целым числом в копейках, валюта RUB | `docs/data-model.md` | На экране человек видит рубли. Копейки — деталь хранения |
| Чужую заявку и чужое решение сервер отклоняет | `docs/architecture.md`, `docs/api.md` | Сценарий S14. Скрытый пункт меню недостаточен |
| Повтор отправки и конфликт двух вкладок не создают вторую заявку | `docs/state-machine.md`, тест-план E2E-07 | Сценарии S06 и S19 |
| Подпись и выдача помечены как демонстрация | `docs/architecture.md` | Сценарий S18 |
| Персональная лента событий | `docs/architecture.md` | Делать только если организаторы подтвердят формулировку про новости |
| PostgreSQL, SQLAlchemy, Alembic | ADR в черновике PR #15 | Не считать выбранным стеком, пока команда не примет ADR |
| Демо-вход только для демонстрационного режима | `docs/architecture.md` | Логин и пароль брать из принятой инструкции запуска |
