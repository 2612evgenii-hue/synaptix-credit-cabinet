# Фиксация версии и сдача

Дата/время/часовой пояс дедлайна **не получены**. Не угадывать их по имени кейса.
Записать подтверждённый timestamp ISO 8601 с offset в `config/team.json` и источник
в журнале; например, формат `YYYY-MM-DDTHH:MM:SS+03:00`.

## До финальной версии

1. Закрыть P0, проверить все строки `docs/requirements.md`.
2. Актуализировать `config/deliverables.json`: статус complete только по факту,
   с путями к исполнимым файлам/отчёту проверки.
3. `make check`, Gitleaks и `make submission-check` должны пройти.
4. Выполнить Docker/E2E на чистом клоне другим участником; записать результат.
5. Проверить исходники/lock-файлы/образы/модели/лицензии, README и notices.
6. Проверить принятый доступ всех участников и жюри. В PDF указан `alfa-hack-2026`.

Личный приватный GitHub-репозиторий даёт collaborator право write, а не read.
Для минимального read-only-доступа жюри нужна организация с ролью Read.
Не считать отправленное приглашение принятым доступом; форму доступа согласует
главный администратор. Приглашение жюри не отправляется скриптами автоматически.

## Неизменяемая ссылка

После финального PR, в чистом `main`:

```sh
git pull --ff-only
make backup
# Только после подтверждения дедлайна и успешной проверки сдачи:
python3 scripts/freeze.py --tag v1.0.0-hackathon.1 --deadline '<ISO8601-с-offset>'
```

Скрипт создаёт локальный manifest и печатает команды для аннотированного тега;
ничего не пушит, не меняет tag и не выпускает GitHub Release автоматически.
Проверить manifest, затем выполнить напечатанные команды до дедлайна.
При наличии настроенного ключа использовать подписанный тег `git tag -s`.
Опубликовать Release с manifest как asset, полным SHA и инструкцией проверки;
отправить **точную ссылку на тег/коммит**, а не меняющийся `main`.
Проверить в удалённом репозитории, что тег указывает на тот же SHA.

Локальные даты коммитов и тегов изменяемы и не доказывают своевременную загрузку.
Дополнительно сохранить URL GitHub Release/CI run и время публикации, подтверждение
отправки на площадке. Финальное соблюдение дедлайна проверяют организаторы.
После дедлайна tag не перемещать; поздние исправления вести отдельно и не выдавать
за принятую версию. Если tag ruleset недоступен по тарифу, неизменяемость —
процессное правило с ограничениями, а полный SHA остаётся основным идентификатором.

## Передаваемый комплект

URL private repo + проверенный доступ жюри, полный SHA/тег, README, Docker-конфигурация,
закреплённые версии, seed/аккаунты, архитектура, API/OpenAPI/коллекция, состояния,
модель данных, сценарии и доказательства запуска, THIRD_PARTY_NOTICES, границы MVP.
Облако и видео — дополнение к проверяемому работающему прототипу.
