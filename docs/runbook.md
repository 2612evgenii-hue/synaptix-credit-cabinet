# Запуск и окружение

## Реализованный локальный frontend

Node 22.12+; проверено с 22.22.2 и npm 10.9.7 на macOS.

```sh
npm ci --prefix apps/web --ignore-scripts
npm run dev --prefix apps/web
```

URL: http://127.0.0.1:4180. Для проверки production-сборки:
`npm run build --prefix apps/web`, затем `npm run preview --prefix apps/web -- --port 4180 --strictPort`.
Остановка Node-сервера — Ctrl+C. Вход через выбор роли, паролей нет.
Демо-сценарий → Начать заново → Подтвердить сброс заменяет локальные заявки
исходным синтетическим набором. Обычный reload сохраняет данные.

Добавлена конфигурация Docker только для frontend:

```sh
docker compose -f compose.frontend.yaml up --build
```

Тот же URL, healthcheck `/health` внутри контейнера. Для остановки:
`docker compose -f compose.frontend.yaml down`. Volumes не нужны: состояние хранится
в браузере. Сборка скачивает образы и npm-пакеты, готовый UI не требует внешних API.
На текущем Mac нет работающего Docker Engine и Compose v2, поэтому контейнерный
запуск здесь **не подтверждён**. Это не замена E2E полного продукта.

## Будущий запуск полного продукта

Следующий раздел задаёт критерии backend-интеграции; они ещё не реализованы.

## Требуемый результат

На обычном ПК с Docker Engine / Docker Desktop и Compose v2:

1. Клонировать точный тег/коммит сдачи.
2. Создать `.env` из `.env.example` с безопасными demo-настройками.
3. Выполнить **одну команду** `docker compose up --build`.
4. Дождаться healthcheck; открыть указанный URL веб-кабинета.
5. Войти под синтетическими customer и bank, пройти `docs/test-scenarios.md`.
6. Перезапустить compose без удаления volumes; убедиться, что заявка сохранилась.

Реализация должна указать проверенные версии Docker/Compose, CPU/RAM/диск,
поддерживаемые архитектуры, порты, URL health/Swagger, тестовые логины/пароли,
время старта, процедуру seed и обычной остановки `docker compose down`.
`down -v` удаляет данные: описать как отдельный намеренный сброс демо.
После первого скачивания образов и пакетов основной сценарий не требует платных
и банковских API; зафиксировать, какие сетевые обращения нужны сборке.

## Предложенные переменные

| Переменная | Значение демо | Назначение |
| --- | --- | --- |
| APP_ENV | demo | включает только синтетический seed |
| WEB_PORT | 3000 | локальный веб-порт |
| API_PORT | 8000 | локальный API-порт |
| INTEGRATIONS_MODE | mock | локальные БКИ/реестр |
| SESSION_SECRET | задаётся локально | будущая аутентификация |

Имена предварительные: синхронизировать с кодом перед реализацией.
Не добавлять зависимость от платного облака в обязательный путь запуска.
